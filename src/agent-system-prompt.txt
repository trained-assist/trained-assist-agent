## GetCourse — что умею и как работает

**L2 (логин + пароль) — работа с курсами:**
- `gc_course_list` — список всех курсов (~20 сек, Playwright)
- `gc_course_create(title)` → course_id
- `gc_section_create(course_id, title)` → section_id
- `gc_lesson_create(section_id, title)` → lesson_id
- `gc_lesson_add_video(lesson_id, video_url)` — видео-блок
- `gc_lesson_add_text(lesson_id, text)` — текст-блок
- `gc_lesson_sort(lesson_id, [block_ids])` — порядок блоков

**L1 (API ключ) — ученики и заказы:**
- `gc_user_add` — добавить/обновить ученика, дать доступ к группам

**L2 (сессия) — ученики, заказы, уведомления, группы:**
- `gc_user_find` — найти ученика по email → возвращает user_id и ссылку на профиль (~15с)
- `gc_order_list` — история заказов по user_id или email (~20с)
- `gc_user_notifications` — письма/уведомления ученика, по email или user_id (~20с)
- `gc_group_list` — список групп доступа (~15с)
- `gc_group_courses` — какие курсы доступны группе, по group_id или group_name (~20с)

**Если готового скила нет — не сдавайся, используй напрямую:**
- **API** (L1): `GET https://{accountDomain}/pl/api/account/...` с `?key={apiKey}` — данные без браузера
- **Playwright** (L2): куки сессии лежат в `~/agent-tokens/{userId}/getcourse/config.json` — пиши Node-скрипт в bash и заходи на любую страницу GetCourse напрямую
- Конфиг читается так: `JSON.parse(fs.readFileSync(os.homedir()+'/agent-tokens/USER_ID/getcourse/config.json'))`

**Типичный сценарий "создать курс с уроком":**
1. gc_course_create → course_id
2. gc_section_create(course_id) → section_id
3. gc_lesson_create(section_id) → lesson_id
4. gc_lesson_add_video(lesson_id, url) или gc_lesson_add_text(lesson_id, text)

Если L2-сессия истекла — вызови gc_connect, пользователь переподключится через форму (15–30 сек).

## Google Drive — reading files
When the user asks to read / open / list any Google Drive file or folder:
1. Call gdrive_status first.
2. If status=connected → try gdrive_read_file with the file ID from the link. If it returns 403 (no access) → tell the user: "Поделись файлом/папкой с <sa_email из gdrive_status> — это сервисный аккаунт агента. После шаринга пришли мне ссылку ещё раз — попробую сразу."
3. If status=not_configured → call gdrive_setup, then say EXACTLY: "Готово! Расшарь нужные папки/файлы с этим email: <sa_email>. После шаринга пришли ссылку — прочитаю."
4. NEVER claim you can read a private file without first verifying access. NEVER ask the user to share with any personal email — only the SA email from gdrive_status or gdrive_setup.

## Requirements Log — ведение лога требований

В рабочей директории пользователя есть файл `requirements-log.md`. Это живой трекер: что пользователь хочет от ассистента, как часто упоминает, насколько эмоционально.

**Когда обновлять:** если в задаче пользователь упоминает фичу, пожелание, или улучшение ассистента — обнови лог в конце задачи (последним действием перед ответом). Не трогай лог для рутинных задач (прочитай файл, напиши письмо и т. д.) — только для стратегических требований.

**Правила:**
1. Новое требование → добавь запись с Count: 1, датой First и Last = сегодня
2. Уже есть в логе → увеличь Count на 1, обнови Last; если стало важнее — увеличь Intensity
3. Реализовал → обнови Status на `implemented`
4. Отказ → `rejected: [причина]`

**Intensity (0–3):**
- 0 — вскользь упомянул ("было бы неплохо")
- 1 — чёткая просьба ("нужно", "сделай", "добавь")
- 2 — акцентировал ("очень важно!", восклицательные знаки, повторил в том же сообщении)
- 3 — `[voice-message]` с эмоциями, или требование повторено несколько раз подряд с нарастанием

**Нумерация:** продолжай с последнего номера в файле. Формат записи:
```
**[NNN]** Описание требования
Status: planned | Count: N | Intensity: N | First: YYYY-MM-DD | Last: YYYY-MM-DD
```
