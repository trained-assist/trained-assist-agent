## 1. Термины

| Термин | Что это | Примеры |
|--------|---------|---------|
| **Агент-ассистент** | Бот широкого профиля. Полный Claude Code агент с MCP-скиллами. Умеет: Weeek, HH, nalog, компании, задачи, голос, файлы. Отвечает развёрнуто, с контекстом сессии. | `@super_personal_assistant_bot`, `trained-assist-tg-bot` |
| **Специализированный бот** (узкий бот) | Бот с конкретными командами под один сценарий. Быстрый, детерминированный. Делегирует нестандартное агенту-ассистенту. | `@cmr_management_bot` (выставки flexi), будущие боты под другие события/продукты |
| **VM-агент** | HTTP-сервер на GCP VM (`trained-assist-agent`). Бэкенд агента-ассистента и точка входа для делегирования. | `https://136-65-7-197.sslip.io` |
| **Профиль** | Единица изоляции. Владеет токенами, сессиями, MCP-скиллами. Один профиль — многие чаты. | `flexi`, `flexi-consult`, `recruiter-skillset` |
| **CHAT_MAPPINGS** | Маппинг Telegram chat_id → профиль. Настраивается в секретах CF Worker. | `{"89994164": "flexi-consult"}` |

## 2. Текущая архитектура (что построено)

### 2.1 Агент-ассистент

```
User (Telegram) → trained-assist-tg-bot (CF Worker)
                      │
                      ├─ simple → quick answer (getQuickAnswer())
                      ├─ voice → Deepgram STR → text
                      │
                      └─ task → POST /run → VM-агент
                                    │
                                    ├─ quick answer (deterministic)
                                    └─ Claude Code --print "<task>"
                                          │
                                          └─ MCP-скиллы (30-weeek, 90-hh, …)
```

**Эндпоинты VM-агента (trained-assist-agent):**

| Метод | Путь | Описание |
|-------|------|----------|
| `GET` | `/health` | Liveness |
| `GET` | `/capabilities?userId=<profile>` | Какие RU-сервисы доступны юзеру |
| `POST` | `/run` | Запуск Claude Code задачи |
| `POST` | `/classify` | Haiku-матч нового сообщения к сессии |
| `POST` | `/admin/refresh-weeek-session` | Обновить Weeek L2 сессию (headless Playwright) |
| `GET` | `/connect/:service` | OAuth/login формы |

### 2.2 Специализированный бот (flexi-exhibition-deal-bot)

Cloudflare Worker. Обрабатывает Telegram webhook для `@cmr_management_bot`.

**Что умеет:**
- Приём команд из Telegram (создание сделок, партнёры, лиды)
- Deep link из каталога выставки → создание сделки в Weeek (`?start=cpmautumn2026_deal_13A01`)
- Site predeal notes: хранение заметок в D1 с каталог-сайта до отправки
- CHAT_MAPPINGS: Telegram chat → профиль Weeek
- Weeek L1 (публичный API) + L2 (приватный API через WEEEK_APP_COOKIE)
- **Авторефреш L2-сессии через VM-агент** (`POST /admin/refresh-weeek-session`)
- **Уведомление пользователя** при рефреше: "🔄 Сессия Weeek обновляется…"
- OCR визиток (Cloudflare AI / внешний API)
- ASR голосовых (Deepgram)
- Message review pipeline: классификация → визитка/задача/контакт/компания/комментарий

**Архитектура узкого бота:**

```
User (Telegram) → @cmr_management_bot (CF Worker)
                      │
                      ├─ команды → детерминированные ответы
                      ├─ deep link → createDealFromCatalog()
                      ├─ голос → Deepgram → text → classify
                      ├─ фото → OCR → визитка
                      │
                      ├─ Weeek L1 API (Bearer token, постоянный)
                      ├─ Weeek L2 API (WEEEK_APP_COOKIE, ~2ч)
                      │      └─ при 401 → VM-агент /admin/refresh-weeek-session
                      │
                      └─ [НЕРЕАЛИЗОВАНО] делегирование агенту-ассистенту
```

## 3. Чего не хватает — Integration Gap

### 3.1 Делегирование нестандартных запросов

Сейчас если пользователь пишет узкому боту что-то вне его сценария (например, "помоги составить письмо партнёру") — бот либо не отвечает, либо выдаёт дефолтное "не понимаю".

**Нужно:** узкий бот должен уметь проксировать задачу агенту-ассистенту и вернуть ответ в тот же чат.

### 3.2 Quick-answer endpoint

Сейчас агент-ассистент делает quick answers только внутри себя (в `runner.js → getQuickAnswer()`). Узкий бот не может получить быстрый ответ без запуска полного Claude Code.

**Нужно:** `POST /quick` — эндпоинт для детерминированных быстрых ответов. Узкий бот спрашивает: "что умеет агент-ассистент для этого юзера?", получает текст за <200ms без Claude.

### 3.3 Capability discovery для upsell

Узкий бот не знает, какие возможности есть у агента-ассистента для конкретного пользователя. Не может подсказать: "хочешь больше? у меня есть HH-рекрутинг, налоговые чеки и т.д."

**Нужно:** `/capabilities` уже есть — расширить до полного списка фич, не только RU-сервисов.

### 3.4 SDK / шаблон нового узкого бота

Сейчас создание нового узкого бота = копирование кода flexi-exhibition-deal-bot и ручная адаптация. Нет стандартного способа:
- Подключить авторефреш сессий
- Настроить CHAT_MAPPINGS
- Настроить делегирование агенту
- Получить capability-карточку для upsell

## 4. Целевая архитектура

### 4.1 Протокол взаимодействия узкого бота с агентом-ассистентом

```
[Узкий бот] ──── POST /quick ────────────────→ [VM-агент]
                  { userId, query }              ← { answer: "...", ms: 45 }
                  быстрый детерминированный ответ

[Узкий бот] ──── POST /run ──────────────────→ [VM-агент]
                  { userId, username, task }      ← 202 { taskId }
                  полный Claude Code агент        ← stream → Telegram

[Узкий бот] ──── GET /capabilities?userId=… ─→ [VM-агент]
                                                ← { capabilities: [...], skills: [...] }
                  что умеет агент для этого юзера

[Узкий бот] ──── POST /admin/refresh-weeek-session ─→ [VM-агент]
                  { profiles: "flexi,flexi-consult" }  ← { ok, cookie }
                  обновить L2 сессию (уже реализовано)
```

### 4.2 Новые эндпоинты VM-агента

#### `POST /quick`

```json
// Request
{
  "userId": "flexi-consult",
  "query": "что умеешь?",
  "chatId": 89994164
}

// Response
{
  "answer": "Вот что я умею для вашего аккаунта:\n• Weeek CRM — сделки, контакты\n• HH — рекрутинг\n...",
  "matched": "capabilities",
  "ms": 38
}
```

Логика: попытка `getQuickAnswer(query, userId)`. Если не матчит — `null` (узкий бот не делегирует, обрабатывает сам или говорит "не знаю").

#### `GET /capabilities` (расширить)

Текущий ответ: `{ "capabilities": ["nalog"] }` — только RU-сервисы.

Расширить до:
```json
{
  "capabilities": ["nalog"],
  "skills": ["weeek", "hh-recruiting", "company-enrichment"],
  "upsell_text": "Агент-ассистент умеет: Weeek CRM, HH-рекрутинг, налоговые чеки, поиск компаний. Напишите @super_personal_assistant_bot для доступа."
}
```

### 4.3 Протокол делегирования (в узком боте)

```js
// В узком боте — стандартный паттерн
async function handleUnknownMessage(env, chatId, userId, text) {
  // 1. Пробуем quick answer
  const quick = await agentQuick(env, userId, text);
  if (quick?.answer) {
    return sendMessage(env, chatId, quick.answer);
  }

  // 2. Делегируем полный /run
  const delegated = await agentRun(env, {
    userId: chatId,        // куда стримить
    username: userId,      // профиль
    task: text,
  });
  if (!delegated.ok) {
    return sendMessage(env, chatId, "Не смог передать запрос ассистенту, попробуйте позже.");
  }
  // Ответ придёт стримингом напрямую из VM → Telegram
}
```

## 6. Use Cases

### UC-1: Юзер пишет узкому боту "что ты умеешь?"

**Сейчас:** бот отвечает только про свои команды (или ничего).  
**Цель:**
1. Узкий бот проверяет, есть ли quick answer у агента-ассистента
2. Возвращает карточку: "Здесь — создание сделок по выставке. Больше возможностей — у @super_personal_assistant_bot: HH-рекрутинг, налоги, задачи."

### UC-2: Юзер пишет узкому боту произвольный вопрос

**Сейчас:** нет обработки → молчание.  
**Цель:**
1. Quick answer → быстрый ответ если матчит
2. Иначе → делегировать `/run` + уведомить "Перенаправляю ассистенту…"
3. Стрим ответа от агента приходит в тот же чат

### UC-3: Weeek L2 сессия истекает в процессе работы

**Сейчас:** ✅ реализовано. Авторефреш + уведомление "🔄 Сессия обновляется…"  
**Ещё нужно:** если рефреш тоже упал — чёткое сообщение "Не удалось обновить сессию, попробуйте ещё раз через 5 минут." + алерт оператору.

### UC-4: Новый узкий бот под другую выставку / продукт

**Сейчас:** копировать flexi-exhibition-deal-bot вручную.  
**Цель:** чеклист для запуска нового узкого бота за 1 день:
1. Fork CF Worker template
2. Заполнить `wrangler.toml` (CHAT_MAPPINGS, AGENT_URL, AGENT_SECRET)
3. Настроить Weeek funnel_id и status_id
4. Деплой

## 7. Архитектурные решения и ограничения

### Почему CF Worker для узкого бота?

- Zero cold start (V8 isolates)
- Встроенный KV, D1, Workers AI
- Дешевле и быстрее EC2/VM для stateless обработки webhook
- Wrangler деплой за секунды

### Почему узкий бот не может сам делать refresh-weeek-session?

CF Workers изолированы — нет доступа к файловой системе и нельзя запустить Playwright. Refresh требует headless Chromium → только VM. CF Worker вызывает VM как HTTP API.

### Почему не MCP?

MCP — протокол для инструментов внутри Claude Code. Узкий бот — отдельный сервис без Claude Code. Взаимодействие через HTTP REST — правильный уровень. MCP не нужен между ботами.

### Почему не один бот?

Узкий бот оптимизирован под конкретный сценарий:
- Детерминированные ответы (без LLM-задержки)
- Специфические команды (`/deals`, `/new_partner`, deep links)
- Своя Telegram-личность (отдельный bot token)
- Отдельный домен ответственности — проще тестировать

## 9. Открытые вопросы

1. **Идентификатор юзера при делегировании:** `/run` принимает `userId` = Telegram chat ID, `username` = профиль. Узкий бот знает оба через CHAT_MAPPINGS. Нужно убедиться что VM корректно стримит в нужный чат.

2. **Тайм-аут при делегировании:** CF Worker имеет CPU limit. Если агент отвечает 30+ секунд — воркер может завершиться раньше ответа. Решение: делегирование асинхронное — воркер возвращает "Передаю…", VM сам стримит в Telegram.

3. **Конфликт уведомлений:** если узкий бот уже отправил "🔄 Сессия обновляется…", а потом агент тоже пишет — дублирование. Нужен флаг "уведомление уже отправлено".

4. **Как называть бота юзеру?** Предложения: "Ассистент" (простое), "Агент" (технично), "Умный помощник" (понятно). Для MVP — оставить как есть, переименовать после.
