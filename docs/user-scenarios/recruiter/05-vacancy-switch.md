# Recruiter — Смена активной вакансии

**Домен:** HeadHunter рекрутинг  
**Суть:** Рекрутер работает с несколькими вакансиями и переключается между ними  
**Зависимость:** HH подключён, 2+ вакансии существуют

---

## Контекст (начальный state)

- HH подключён
- Вакансии: "Python Developer" (активная), "DevOps Engineer", "QA Lead"
- ATS-критерии настроены для Python Developer

---

## Сценарий A — Переключение вакансии

### A1 — Смена активной вакансии

```
User: переключись на вакансию DevOps Engineer
```

**Ожидаем:**
- Бот обновляет `contexts/hh/active_vacancy.json`
- Подтверждение: "Активная вакансия: DevOps Engineer (ID: 22222)"

**Validation:**
- `active_vacancy.json` содержит правильный vacancy_id
- Предыдущие данные Python Developer не теряются

---

### A2 — Запрос откликов после смены

```
User: покажи отклики
```

**Ожидаем:**
- Отклики по DevOps Engineer (не по Python Developer)
- Бот не путает вакансии

---

### A3 — ATS-критерии для новой вакансии

```
User: задай критерии: нужен Kubernetes, Terraform, опыт CI/CD
```

**Ожидаем:**
- Критерии сохраняются для DevOps Engineer, не перезаписывают Python Developer
- `ats_criteria.json` должен хранить критерии per-vacancy или быть очищен

**Validation:**
- Если возвращаемся к Python Developer — критерии там не изменились

---

### A4 — Возврат к предыдущей вакансии

```
User: переключи на Python Developer
```

**Ожидаем:**
- Активная вакансия снова Python Developer
- ATS-критерии загружаются для неё

---

## Сценарий B — Параллельная работа (нет в текущем UX, но важный edge case)

### B1 — Спросить про другую вакансию без переключения

```
User: сколько откликов у DevOps Engineer?
```

**Ожидаем:**
- Бот понимает что речь о другой вакансии
- Даёт ответ не переключая активную
- Или явно спрашивает: "Переключиться на DevOps Engineer?"

---

### B2 — Создать новую вакансию

```
User: создай вакансию "Frontend React Developer"
```

**Ожидаем:**
- Бот направляет на HH (вакансии создаются через веб, не через API)
- Или показывает черновик вакансии для публикации
- Объясняет процесс

---

## Edge Cases

| Ситуация | Ожидаемое поведение |
|----------|---------------------|
| Вакансия не найдена по имени | "Не найдена вакансия с таким названием. Вот список: ..." |
| Вакансия закрыта/архивирована | Предупреждение, уточняет нужно ли работать с архивной |
| Вакансия только одна | Не нужно выбирать — автоматически активная |
| Активная вакансия удалена на HH | Уведомляет рекрутера при следующем запросе |

---

## Проверяемые инварианты

1. `active_vacancy.json` всегда содержит валидный vacancy_id
2. ATS-критерии per-vacancy не перезаписывают друг друга
3. Все last-seen данные (seen_ids, skipped кандидаты) привязаны к vacancy_id
4. После переключения все запросы идут для новой активной вакансии
