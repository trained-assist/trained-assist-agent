# Recruiter — Холодный поиск (проактивный)

**Домен:** HeadHunter рекрутинг — поиск без откликов  
**Суть:** Рекрутер ищет кандидатов, которые не откликались — по резюмебазе HH  
**Зависимость:** HH подключён, активная вакансия (необязательно)

---

## Контекст (начальный state)

- HH подключён
- Активная вакансия: Python Developer (опционально)
- Ранее сохранённых cold-search запросов: нет

---

## Сценарий A — Первый поиск

### A1 — Запрос холодного поиска

```
User: найди python разработчиков в Москве senior уровня
```

**Ожидаем:**
- Бот формирует search query для HH API (`GET /resumes?text=python&area=1&experience=between3And6`)
- Показывает результаты: имя, краткое резюме, ссылка
- Сообщает кол-во найденных

**Validation:**
- API call: `GET https://api.hh.ru/resumes` с правильными параметрами
- area=1 (Москва), experience соответствует "senior"

---

### A2 — Уточнение поиска

```
User: добавь фильтр — только с опытом FastAPI
```

**Ожидаем:**
- Новый запрос с `text=python fastapi`
- Обновлённый список результатов

---

### A3 — Сохранение запроса

```
User: сохрани этот поиск как "python-senior-msk"
```

**Ожидаем:**
- Параметры запроса сохраняются в `contexts/hh/saved_searches.json`
- Подтверждение: "Поиск 'python-senior-msk' сохранён"

**Validation:**
- `saved_searches.json` содержит запись с именем и параметрами

---

### A4 — Повторный запуск сохранённого поиска

```
User: запусти поиск python-senior-msk
```

**Ожидаем:**
- Бот загружает параметры из `saved_searches.json`
- Выполняет тот же запрос заново (свежие результаты)
- Помечает уже виденных кандидатов (если такие есть)

---

## Сценарий B — Отсеивание и работа с результатами

### B1 — Просмотр конкретного резюме

```
User: покажи резюме второго в списке
```

**Ожидаем:**
- Полное резюме кандидата из HH API
- Структурировано: опыт, стек, образование, зарплатные ожидания

---

### B2 — Написать кандидату из холодного поиска

```
User: напиши Дмитрию Волкову, предложи рассмотреть нашу вакансию
```

**Ожидаем:**
- Генерирует холодное outreach-сообщение
- Учитывает резюме кандидата, упоминает конкретные совпадения со стеком
- Показывает черновик

**Validation:**
- Сообщение персонализировано (не шаблон без имени)
- Упоминает что-то конкретное из резюме (технологии, опыт)

---

### B3 — Отметить кандидата как "не интересен"

```
User: Петренко не интересен, пропускаем
```

**Ожидаем:**
- Кандидат помечается в локальной базе как `skipped`
- При следующем поиске не показывается
- Подтверждение

---

## Сценарий C — Обновление критериев поиска

### C1 — Расширить географию

```
User: расширь поиск — добавь Питер
```

**Ожидаем:**
- Обновлённый запрос с `area=1,2` (Москва + Питер)
- Показывает новые результаты

---

### C2 — Пересмотреть всех пропущенных

```
User: покажи кого я пропустил в этом поиске
```

**Ожидаем:**
- Список кандидатов со статусом `skipped`
- Возможность вернуть в рассмотрение

---

## Сценарий D — Обновление данных (seen_ids логика)

```
User: синхронизируй холодный поиск
```

**Ожидаем:**
- Новые кандидаты из HH (которых не было раньше) добавляются
- Уже просмотренные (`seen_ids`) не показываются повторно
- Отчёт: "Новых кандидатов: X"

**Validation:**
- `seen_ids` хранятся на диске между сессиями (персистентно)
- Уже контактировали с кандидатом → помечается как contacted

---

## Edge Cases

| Ситуация | Ожидаемое поведение |
|----------|---------------------|
| Поиск ничего не нашёл | "По вашему запросу резюме не найдены. Попробуйте расширить критерии" |
| Кандидат закрыл резюме | Плавная обработка 404 от HH API |
| Имя поиска уже занято | "Поиск 'python-senior-msk' уже существует. Перезаписать?" |
| HH квота на просмотр резюме исчерпана | Понятное сообщение про лимиты HH |
| Все результаты уже просмотрены | "Новых кандидатов не найдено" |

---

## Проверяемые инварианты

1. `seen_ids` персистентны — не сбрасываются при рестарте агента
2. Холодный outreach-запрос персонализирован на основе резюме
3. Skipped кандидаты не возвращаются в следующий поиск автоматически
4. Параметры сохранённого поиска точно воспроизводят исходный запрос
