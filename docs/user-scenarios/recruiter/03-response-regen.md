# Recruiter — Перегенерация ответа кандидату

**Домен:** HeadHunter рекрутинг — управление перепиской  
**Суть:** Рекрутер не доволен сгенерированным сообщением → просит переделать  
**Зависимость:** HH подключён, активная вакансия, кандидат выбран

---

## Контекст (начальный state)

- Активная вакансия: Python Developer
- Кандидат: Алексей Смирнов (neg_id: 99001)
- ATS-результат: partial fit
- Черновик сообщения: был показан, но не отправлен

---

## Сценарий A — Перегенерация с общей просьбой

### A1 — Первичная генерация

```
User: напиши Алексею Смирнову — хотим пригласить на интервью
```

**Бот генерирует:**
```
Здравствуйте, Алексей! Мы рассмотрели ваше резюме и хотели бы пригласить вас
на техническое интервью по позиции Python Developer...
```

---

### A2 — "Не нравится, перегенерируй"

```
User: перегенерируй, слишком официально
```

**Ожидаем:**
- Бот генерирует новый вариант в более неформальном тоне
- Не отправляет старый вариант
- Показывает черновик

**Validation:**
- Новый вариант заметно отличается от первого
- Тон более дружелюбный/живой

---

### A3 — Ещё раз перегенерируй

```
User: ещё раз, покороче
```

**Ожидаем:**
- Третий вариант, короче предыдущего
- Бот не путается — понимает что всё ещё говорит про Алексея

---

### A4 — Принять и отправить

```
User: ок, отправляй
```

**Ожидаем:**
- Отправляется ПОСЛЕДНИЙ сгенерированный вариант (не первый)
- Подтверждение отправки

---

## Сценарий B — Уточнение конкретных деталей

### B1 — Попросить добавить деталь

```
User: напиши что интервью в формате онлайн, во вторник в 15:00
```

**Ожидаем:**
- Бот генерирует сообщение с указанием времени и формата
- Структурированно: время, формат, что нужно подготовить

---

### B2 — Убрать лишнее

```
User: убери абзац про компанию, слишком длинно
```

**Ожидаем:**
- Бот редактирует черновик
- Понимает "убери" как инструкцию к редактированию, не как отказ

---

### B3 — Полная переработка с подсказкой

```
User: перепиши совсем по-другому — мы небольшая команда, хотим живого кандидата, без корпоративщины
```

**Ожидаем:**
- Неформальный, живой текст
- Без "Уважаемый", без "рассмотрели вашу кандидатуру"

---

## Сценарий C — Генерация по шаблону рекрутера

*Предусловие: рекрутер настроил identity (`recruiter_identity` context)*

```
User: напиши Смирнову по нашему стилю
```

**Ожидаем:**
- Бот загружает `contexts/hh/message_config.json` — агентство, подпись, правила
- Сообщение соответствует настроенному стилю

**Validation:**
- Подпись в конце письма соответствует настроенной в `message_config`
- Упоминается агентство если задано

---

## Сценарий D — Массовый ответ на похожие отклики

```
User: напиши одинаковое приглашение топ-3 кандидатам
```

**Ожидаем:**
- Бот генерирует 3 персонализированных сообщения (разные имена)
- Показывает все три, предлагает отправить
- После "ок" — 3 отдельных API call

**Validation:**
- Каждое сообщение содержит правильное имя кандидата
- Ни одно не отправлено до подтверждения

---

## Edge Cases

| Ситуация | Ожидаемое поведение |
|----------|---------------------|
| "Перегенерируй" без активного черновика | "Для кого генерируем?" |
| "Отправляй" без подтверждённого черновика | Уточняет какой вариант |
| Имя кандидата — нестандартное / латиница | Имя передаётся как есть |
| Кандидат уже получал сообщения | Бот учитывает историю в промпте |
| Кандидат ответил между генерацией и отправкой | Предупреждение: у кандидата новое сообщение |

---

## Проверяемые инварианты

1. Отправка происходит только после явного "отправляй" / "да" / подтверждения
2. Каждая перегенерация использует историю кандидата как контекст
3. Черновик не теряется при смене темы и возврате
4. Стиль рекрутера из `message_config` применяется последовательно
