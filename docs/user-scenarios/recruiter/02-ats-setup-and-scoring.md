# Recruiter — ATS: Настройка критериев и скоринг

**Домен:** HeadHunter рекрутинг — ATS-подбор  
**Пресловарий ATS (Applicant Tracking System):** хранение критериев подбора + автооценка кандидатов  
**Зависимость:** HH подключён, активная вакансия выбрана

---

## Контекст (начальный state)

- HH токен: **подключён**
- Активная вакансия: **выбрана** (Python Developer, ID 12345)
- ATS-критерии: **не настроены**
- Кандидатов в базе: 10 штук (загружены при синке)

---

## Сценарий A — Первичная настройка критериев

### A1 — Задать критерии текстом

```
User: настрой АТС: нужен senior python, опыт FastAPI, желательно ML
```

**Ожидаем:**
- Бот парсит: обязательные (Python senior, FastAPI), желательные (ML)
- Сохраняет в `contexts/hh/ats_criteria.json`
- Подтверждает что сохранено, перечисляет критерии

---

### A2 — Уточнение критериев

```
User: добавь ещё — обязательно знание PostgreSQL
```

**Ожидаем:**
- Бот обновляет критерии, добавляет PostgreSQL в `required`
- Не стирает предыдущие
- Показывает полный обновлённый список

**Validation:**
- `ats_criteria.json` содержит и FastAPI, и PostgreSQL в `required`

---

### A3 — Просмотр текущих критериев

```
User: какие у нас критерии подбора?
```

**Ожидаем:**
- Бот читает `contexts/hh/ats_criteria.json`
- Выводит структурированный список: обязательные / желательные

---

## Сценарий B — Скоринг кандидатов

### B1 — Массовый пересчёт

```
User: пересчитай всех кандидатов по новым критериям
```

**Ожидаем:**
- Бот скорит всех кандидатов в базе через OpenRouter (DeepSeek)
- Сообщает прогресс: "Оцениваю... 1/10, 2/10..."
- Финальный отчёт: X fit, Y partial, Z no-fit

**Validation:**
- Ни один вызов не идёт через Claude Code (только OpenRouter)
- Каждый кандидат получает `ats_result` в своём `.json` файле

---

### B2 — Скоринг одного кандидата вручную

```
User: оцени резюме Марины Ковалёвой
```

**Ожидаем:**
- Детальная оценка: по каждому критерию — passed/failed/partial
- Общий вердикт: fit / partial / no-fit
- Обоснование на русском языке

---

### B3 — Просмотр топа по оценке

```
User: покажи топ-5 кандидатов
```

**Ожидаем:**
- Список 5 лучших по ATS-score
- Для каждого: имя, оценка, ключевые совпадения с критериями

---

### B4 — Фильтр по оценке

```
User: покажи только тех кто прошёл по всем критериям
```

**Ожидаем:**
- Только кандидаты с `ats_result.verdict === "fit"`
- Если никого — честное "никто не прошёл все обязательные критерии"

---

## Сценарий C — Смена критериев и пересчёт

```
User: ладно, уберём обязательность PostgreSQL — пусть будет желательно
```

**Ожидаем:**
- Бот обновляет критерии
- Предлагает пересчитать кандидатов
  
```
User: да, пересчитай
```

**Ожидаем:**
- Пересчёт только тех, у кого `ats_result` мог измениться
- Кандидаты, которые уже были fit, не пересчитываются (экономия токенов)

**Validation:**
- После обновления критериев и пересчёта — разница в fit/no-fit видна

---

## Edge Cases

| Ситуация | Ожидаемое поведение |
|----------|---------------------|
| Критерии не заданы, просят скоринг | "Сначала настройте критерии подбора" |
| Резюме кандидата пустое / не загрузилось | Оценка "не определена", не краш |
| OpenRouter недоступен | Понятная ошибка, задача можно повторить |
| 100+ кандидатов | Пакетная обработка, не падает по памяти/времени |
| Критерии на английском, резюме на русском | Оценка всё равно корректная (LLM справляется) |

---

## Проверяемые инварианты

1. Скоринг всегда через OpenRouter — никогда не через Claude Code
2. `ats_criteria.json` всегда JSON с ключами `required[]` и `optional[]`
3. Пересчёт не стирает историю переписки с кандидатом
4. Повторный скоринг одного кандидата перезаписывает `ats_result`, не дублирует
