# Recruiter — Полный сквозной сценарий (End-to-End)

**Домен:** HeadHunter рекрутинг  
**Длина:** ~15–20 шагов  
**Профиль:** `recruiter` (или любой, у которого HH-токен подключён)  
**Охват:** от первого запуска до отправки ответа кандидату

---

## Контекст (начальный state)

- Пользователь только что создал профиль
- HH-токен: **НЕ подключён**
- Вакансий нет
- Кандидатов нет

---

## Сценарий

### Шаг 1 — Подключение HH

```
User: подключи headhunter
```

**Ожидаем:**
- Бот возвращает ссылку на OAuth авторизацию HH
- Ссылка вида `https://hh.ru/oauth/authorize?...`
- Бот объясняет, что нужно открыть ссылку и авторизоваться

**Validation:**
- Response содержит URL с `hh.ru/oauth`
- Quick answer (не тратит токены Claude)

---

### Шаг 2 — Проверка подключения (после OAuth)

*Предположим: OAuth прошёл, токен сохранён в `~/agent-tokens/{username}/hh`*

```
User: всё подключил
```

**Ожидаем:**
- Бот подтверждает подключение
- Предлагает следующий шаг (выбрать вакансию)

---

### Шаг 3 — Просмотр вакансий

```
User: покажи мои вакансии
```

**Ожидаем:**
- Список вакансий с HH API (`GET /vacancies/mine`)
- Для каждой: название, статус (published/draft), кол-во откликов
- Если вакансий нет — подсказывает как создать

**Validation:**
- API call: `GET https://api.hh.ru/vacancies/mine`
- Ответ содержит список или сообщение "вакансий нет"

---

### Шаг 4 — Выбор активной вакансии

```
User: сделай активной "Python Developer"
```

**Ожидаем:**
- Бот устанавливает активную вакансию в context store
- Подтверждает: "Активная вакансия: Python Developer (ID: 12345)"

**Validation:**
- Файл `contexts/hh/active_vacancy.json` создан/обновлён
- `value.vacancy_id` соответствует ID выбранной вакансии

---

### Шаг 5 — Настройка ATS-критериев

```
User: настрой критерии подбора: нужен Python от 3 лет, желательно FastAPI,英语 B2+
```

**Ожидаем:**
- Бот сохраняет критерии в context store
- Подтверждает: перечисляет обязательные и желательные требования

**Validation:**
- Файл `contexts/hh/ats_criteria.json` создан
- Содержит `required` и `optional` поля
- Следующий скоринг будет использовать эти критерии

---

### Шаг 6 — Просмотр откликов

```
User: покажи отклики
```

**Ожидаем:**
- Список кандидатов по активной вакансии
- Для каждого: имя, резюме (кратко), оценка ATS (если уже посчитана)
- Сортировка: сначала новые или высокооценённые

**Validation:**
- API call: `GET https://api.hh.ru/negotiations?vacancy_id={id}`
- Ответ содержит имена кандидатов + резюме-сводку

---

### Шаг 7 — Оценка конкретного кандидата

```
User: оцени Ивана Петрова
```

**Ожидаем:**
- Бот загружает резюме кандидата
- Прогоняет через ATS-критерии (LLM-оценка через OpenRouter/DeepSeek)
- Возвращает: оценка (fit/partial/no-fit), обоснование по каждому критерию

**Validation:**
- Нет вызова Claude Code — используется OpenRouter напрямую
- Результат сохраняется в `agent-data/hh/{username}/candidates/{neg_id}.json`

---

### Шаг 8 — Генерация ответа кандидату (приглашение)

```
User: напиши Ивану Петрову что приглашаем на интервью
```

**Ожидаем:**
- Бот генерирует персонализированное сообщение
- Учитывает имя, резюме, стиль общения рекрутера
- Показывает черновик сообщения и спрашивает подтверждение

**Validation:**
- Сообщение содержит имя кандидата
- Упоминает вакансию или компанию
- Вежливый тон, без шаблонных банальностей

---

### Шаг 9 — Отправка сообщения

```
User: отправляй
```

**Ожидаем:**
- API call: `POST /negotiations/{neg_id}/messages`
- Бот подтверждает отправку с текстом сообщения

**Validation:**
- HH API был вызван (не просто "ок")
- Сообщение сохранено в локальной истории кандидата

---

### Шаг 10 — Отказ кандидату

```
User: Сидорову откажи
```

**Ожидаем:**
- Бот использует rejection template (если настроен) или дефолтный
- Показывает текст — спрашивает "отправляю?"
- После подтверждения — отправляет через HH API

**Validation:**
- Текст отказа вежливый, содержит имя кандидата `{firstName}`
- API call с правильным neg_id

---

### Шаг 11 — Синхронизация новых откликов

```
User: синхронизируй отклики
```

**Ожидаем:**
- Бот делает инкрементальный синк (только изменившиеся кандидаты)
- Сообщает: "X новых откликов, Y кандидатов обновились"
- Не пересинхронизирует тех, у кого `updated_at` не изменился

**Validation:**
- API calls только для кандидатов с `updated_at > last_hh_message_at`
- Новые кандидаты появились в `candidates/`

---

## Edge Cases в этом сценарии

| Ситуация | Ожидаемое поведение |
|----------|---------------------|
| HH токен протух во время работы | Бот детектирует 401, предлагает переавторизоваться |
| Вакансия не выбрана, просят отклики | Бот просит сначала выбрать активную вакансию |
| Кандидат уже получил сообщение | Бот предупреждает перед повторной отправкой |
| HH API недоступен (timeout) | Бот сообщает об ошибке, не падает |
| Пустой список вакансий | Понятное сообщение, не "undefined" или стектрейс |

---

## Проверяемые инварианты

1. **Ни один шаг рекрутинга не спаунит Claude Code** — только MCP tools через OpenRouter
2. **State персистентен** — после рестарта агента active_vacancy и criteria сохранены
3. **Сообщения не отправляются без подтверждения** — всегда показывается черновик
4. **Токен кандидата хранится надёжно** — `mode 0o600`, не попадает в логи
