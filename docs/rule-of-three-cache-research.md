# Правило трёх повторов — ресёч по фича-кэшу вызовов

**Статус:** ресёч (перед реализацией). **Вердикт:** реально, риск средний, ценность высокая.

## Идея

Когда пользователь третий раз просит одно и то же действие, дёргающее дорогой вызов (API / bash / MCP / LLM), система «упаковывает» этот эндпоинт в дешёвый быстрый ответ: узнаёт паттерн вопроса и отдаёт результат из кэша/шортката, не вызывая дорогую модель или внешний API.

Связка из трёх слоёв: **логгер → детектор повторов → кэш/шорткат**.

## 1. Логирование

Единая точка перехвата всех внешних вызовов. По каждому вызову пишем:

- имя инструмента (`tool`)
- нормализованные аргументы
- `args_hash`
- результат
- latency
- стоимость (токены / деньги / время)

Условие осуществимости: **единая точка перехвата**. В MCP-слое она есть — все вызовы проходят через один диспетчер.

## 2. Детекция повторов

| Уровень | Ключ | Что ловит |
|---------|------|-----------|
| **A** | только эндпоинт (`tool`) | повторное использование функции независимо от аргументов |
| **B** | `tool` + `args_hash` | идентичные вызовы — точное переиспользование результата |
| **C** | семантический (эмбеддинги) | концептуально похожие запросы |

Счётчик частоты ведётся по ключу. Порог срабатывания — **3 повтора**.

## 3. Кэширование ответа

Два механизма:

- **Exact-cache** — возвращает сохранённый результат для детерминированных / медленно меняющихся данных (напр. реквизиты компании по ИНН).
- **Learned shortcut** — после 3-го повтора авто-генерирует лёгкое правило маршрутизации: ловит форму вопроса и отдаёт ответ, минуя дорогую модель.

## Ключевые риски

1. **Устаревание данных** — нужна TTL-политика на кэш.
2. **Нормализация аргументов** — расхождения в нормализации → ложные промахи/попадания кэша.
3. **Ложные попадания на мутациях** — кэшировать только read-only; мутации (create/update/delete/run) не кэшить (white-list).
4. **Учёт стоимости** — считать экономию, чтобы доказать пользу.

## План внедрения (4 фазы)

- **Фаза 0** — логгер + счётчики повторов.
- **Фаза 1** — exact-cache на read-only эндпоинтах.
- **Фаза 2** — learned-shortcut на 3-м повторе + fallback на реальный вызов.
- **Фаза 3** — дашборд экономии (сколько дорогих вызовов сэкономлено).

## Открытые вопросы (нужны ответы перед стартом)

1. **Порог** — считать 3 повтора подряд или 3 всего (накопительно)?
2. **Ключ кэша** — уровень A (эндпоинт) или B (эндпоинт + args_hash)?
3. **Где интерсептор** — в какой точке ставим единую перехватку вызовов?
